# 架構

> 現況（2026-09）加上產品化的路。產品前提看 `product.md`。

## 現況：三層，沒有後端

```
trip.js          這趟旅行的內容。換一趟旅行只換這個檔。
   ↓
app.js           渲染與推導。不含任何日期、班號、地名、金額。
   ↓
localStorage     這台裝置的個人狀態。命名空間 = meta.id。
```

**唯一的例外是 `manifest.webmanifest`** —— 瀏覽器在任何 script 之前就讀它，所以 app 名稱必須手動同步。`check-trip.mjs` 會擋住不一致。

### 內容的三個來源，優先序由低到高

跟隊模式的每一張卡都是這樣組出來的：

| 來源 | 在哪 | 誰寫的 | 何時用 |
|---|---|---|---|
| **推導** | `derive()` in `app.js` | 沒有人 | 事件有時間但沒人寫過內容 |
| **行程內建** | `event.brief` in `trip.js` | 規劃的人（改程式碼） | 有寫就蓋掉推導 |
| **本機覆寫** | `localStorage[id.briefs.v1]` | 帶隊的人（在 app 裡改） | 有寫就蓋掉上面兩層 |

三條規則，破壞任何一條都會出事：

1. **覆寫只蓋文字，永遠不蓋時間。** 時間窗一律來自 `trip.js`。不然行程表和跟隊模式會各說各話。
2. **覆寫是逐欄位的。** 只填了「一句話」不會把步驟清空。
3. **沒有人寫過的內容，畫面不會假裝有。** 推導卡片沒有步驟、沒有硬牆、沒有可展開的細節，也拿不到「這段要抓緊」的紅色處理。

推導這一層是**產品化的關鍵**，不是便利功能：它讓一份全新的 `trip.js` 在建立當天就能跑跟隊模式，而那是第二趟旅行唯一的起點狀態。

### 跟隊模式的狀態機

`followState(t)` 是一個純函式：給一個時刻，回傳畫面該是什麼。沒有副作用、沒有儲存的狀態、沒有「目前選到哪一段」。

| 狀態 | 條件 | 畫面 |
|---|---|---|
| `before` | 還沒到第一個事件那天 | 出發前，還有 N 天 |
| `free` | 下一件事不是今天 | 今天沒有要趕的事＋指名下一件 |
| `later` | 距開始 > 45 分 | 接下來 |
| `soon` | 距開始 < 45 分 | 快到了 |
| `go` | 已經在時間窗內 | 現在 |
| `tight` | 同上，且 `level==='critical'` 且有人寫過 | 這段要抓緊（紅） |
| `done` | 沒有下一件事了 | 旅程完成 |

倒數的目標：**開始前指開始，開始後指 `wall`（真死線），沒有 wall 才指結束**。

`?at=<時間>` 會換掉這個函式的「現在」，畫面上標成預覽。行程列的「看跟隊畫面」走同一條路。

### localStorage key

全部前綴 `meta.id`，換 id 等於換一份乾淨的狀態。

| key | 內容 |
|---|---|
| `{id}.plans.v1` | 自訂行程 |
| `{id}.todos` | 共同待辦的勾選（**keyed by todo id，不是陣列位置**） |
| `{id}.todos.mine.v1` | 我的待辦 |
| `{id}.briefs.v1` | 帶隊的人寫的跟隊內容 |
| `{id}.mode` | 上次在哪個模式 |
| `{id}.theme` | 亮／暗 |

**所有讀取都當成敵意輸入**：型別錯、null、亂七八糟的 JSON 都不能讓畫面掛掉。smoke 有對應的測試。

## 產品化：三件事，互相獨立

目前的東西是一個**單人、單趟、內容靠手寫**的工具。變成產品要補三個洞，**它們彼此獨立，可以分開做**：

| # | 洞 | 現在 | 需要 |
|---|---|---|---|
| A | 內容誰來寫 | 手寫或改程式碼 | **AI 生成** |
| B | 內容怎麼給別人 | 重新部署 | **後端同步** |
| C | 一個人好幾趟 | 一份 `trip.js` | **多行程＋切換** |

**建議順序：A → C → B。** A 的價值最高而且不需要後端；B 最貴而且會把整個東西從「靜態網站」變成「要維運的服務」。

---

## A. 接 AI 生成內容

### 要 AI 做什麼

不是聊天。是一個**結構化生成**任務：

> 輸入：一筆行程事件（時間、類型、標題、備註、路線）＋這趟旅行的上下文
> 輸出：`{line(≤12字), because, steps(≤4), need, fallback}`

這件事**小、有明確 schema、可以驗證**（`check-trip.mjs` 的規則就是驗收標準）。適合用結構化輸出（`output_config.format`）直接拿到 JSON，不要靠 prompt 叫它「只回 JSON」。

### 三條路

| | 1. 複製貼上 | 2. BYOK（瀏覽器直打） | 3. 自架代理 |
|---|---|---|---|
| 怎麼運作 | app 產生 prompt，人貼到 Claude，把 JSON 貼回來 | 使用者存自己的 API key，瀏覽器直接呼叫 API | Cloudflare Worker 之類的持有金鑰 |
| 後端 | 無 | 無 | 有（但很小） |
| 金鑰風險 | 無 | **金鑰暴露在瀏覽器** | 無（金鑰在伺服器） |
| 誰付錢 | 使用者自己 | 使用者自己 | 你 |
| 能給別人用 | 勉強 | 不行 | 可以 |
| 適合 | 今天就能做 | 只有自己用 | 真的要當產品 |

關於路 2，官方文件寫得很直白（TypeScript SDK 的 `dangerouslyAllowBrowser`）：

> Enabling the `dangerouslyAllowBrowser` option can be dangerous because it exposes your secret API credentials in the client-side code. […] **Internal tools:** If the application is used solely within a controlled internal environment where the users are trusted, the risk of credential exposure can be mitigated.

也就是說 **BYOK 只在「自己用」的前提下可接受**，不能拿來給那四個同行的人用。這個 repo 是公開的，更不能把任何金鑰放進程式碼。

（本專案零相依，真的要打的話用 `fetch` 直接打 Messages API，不要為了這個引入 SDK。）

### 模型與成本

| 模型 | ID | 輸入 $/MTok | 輸出 $/MTok |
|---|---|---|---|
| Claude Opus 5 | `claude-opus-5` | $5.00 | $25.00 |
| Claude Sonnet 5 | `claude-sonnet-5` | $2.00 | $10.00 |
| Claude Haiku 4.5 | `claude-haiku-4-5` | $1.00 | $5.00 |

**預設用 `claude-opus-5`。** 一整趟旅行（9 個事件一次生成）大概是 3k 輸入 + 4k 輸出 ≈ **$0.12**。這是**一趟旅行一次**的成本，不是每次開 app。為了省這個錢降級模型不划算 —— 這些字是要給人在機場照著做的。

其他實作要點：
- 用 adaptive thinking（`thinking:{type:"adaptive"}`），effort 用預設就好，這個任務不難
- 生成完**一定要跑 `check-trip.mjs` 的同一套規則**再存；12 字和 4 步是硬限制，模型會超過
- 生成的內容要標記來源（誰寫的：人 / AI），帶隊的人要能一眼看出哪些沒被檢查過

### 更進一步：AI 帶隊

現在的狀態機是純時鐘推導的。真正的「AI 帶隊」是讓它能處理**計畫之外的事**：班機延誤、有人走丟、下大雨。那需要即時輸入（至少要有人按一下「我們延誤了」），而**輸入要傳給其他人就需要 B**。所以這件事排在 B 後面。

## B. 後端同步（最貴的那個）

### 目前為什麼不需要

**共同的東西已經有同步機制了 —— 那就是部署。** `trip.js` 跟著網站走，五個人打開看到的都一樣。這是靜態網站免費送的「同步」。

真正沒解的只有一件事：**帶隊的人在現場改的東西傳不出去。**

### 什麼時候非做不可

出現以下任一個就該做，在那之前不要：

- 帶隊的人需要在**旅行途中**改內容並讓其他人看到
- 需要知道其他人**看到了沒有／到了沒有**
- 一個人要管理**好幾趟**旅行並分給不同的人
- AI 帶隊要能回應現場變化（見上）

### 做的話最小形狀

不要一步跳到「使用者系統」。最小可行是：

- 一個 KV 存 `tripId → trip JSON`（Cloudflare Workers KV / D1 都夠）
- 寫入要一把**每趟旅行各自的**密鑰，帶隊的人有，跟隊的人沒有
- 跟隊端仍然是靜態網站，開機抓一次 JSON，抓不到就用打包進去的 `trip.js`（**離線必須還能動，這是 PWA**）
- 沒有帳號、沒有登入。連結本身就是權限。

這一步會把「靜態網站」變成「要維運的服務」（費用、濫用、資料保存、隱私）。**這是一個產品決定，不是技術決定。**

---

## C. 多行程

`meta.id` 已經是命名空間，所以資料層早就準備好了。缺的是：

- 一個行程清單頁（現在的首頁變成某一趟的頁）
- `trip.js` 從「打包進去的檔案」變成「可以載入的資料」
- `manifest.webmanifest` 的名字不能再跟著某一趟旅行（這是目前唯一寫死的地方）

**做 A 之前先不要做 C。** 沒有內容生成的話，多行程只是多幾份要手寫的檔案。
